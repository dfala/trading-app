# Milestone 23 Plan: Daily Audit Trail And Report Evidence

## Summary

Strengthen the daily paper-trading report so it answers the operator's core review questions: what happened, why it happened, who touched the runtime, which fills affected the ledger, what evidence backs the summary, and where the persisted report lives.

This milestone supports the functional-app completion spec areas for reporting, explainability, audit trail, operator safety, dashboard visibility, and reproducible paper-trading evidence.

## Key Changes

- Add report metadata with report id, schema version, evidence sources, and markdown path.
- Include broker fills in `PaperPortfolioReport` so reports can connect orders to fills and ledger effects.
- Extend trade explanations with:
  - broker order id
  - fill ids
  - signal rationale
  - ledger trace evidence
- Add daily fill details to the daily report.
- Add operator action summaries to the daily report.
- Add runtime event summaries to the daily report.
- Add learning recommendation summaries to the daily report when a nightly run is available.
- Add benchmark comparison scaffolding that is explicit when unavailable.
- Render the new audit sections in the Markdown report.
- Surface report metadata and audit-trail counts in the dashboard.
- Wire runtime-generated reports to include operator controls, runtime events, learning state, and the expected markdown path.

## Non-Goals

- No live trading.
- No real-money path.
- No new trading strategy.
- No natural-language LLM integration.
- No broker statement import yet.
- No fully filing-grade tax output.

## Acceptance Criteria

- Daily reports include report metadata and persisted markdown path when generated by the runtime.
- Daily reports list fills and connect filled orders to internal ledger evidence.
- Operator controls appear in the report.
- Runtime events appear in the report.
- Learning recommendations appear when available and remain recommendation-only.
- Benchmark comparison is present and clearly marked unavailable when there is no benchmark evidence.
- Dashboard shows audit-trail and report metadata signals.
- Existing persisted reports remain recoverable when optional new fields are absent.
